# Safety

- **Loopback only.** The server binds `127.0.0.1` (`SFPRIV_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it). The container runs as a non-root user, read-only, with every capability dropped. The Host header must be a loopback name or on `LAB_ALLOWED_HOSTS` (a malformed value such as `[::1]evil` is refused, and a bad `LAB_ALLOWED_HOSTS` entry stops the server at start-up with a message); writes must be same-origin.
- **Mock makes zero outbound calls.** Netguard is an in-process guard, not an operating-system sandbox. It wraps `fetch`, `net.Socket.connect`, `dns.lookup`, the `dns.resolve*` family and `dgram` `send`, with a self-test (the doctor runs it) and tests that assert zero attempts across whole scenario runs and a whole API session. What it does not cover: a worker thread or child process (the lab starts none, and a test greps for them), a native addon, code that restores the originals, and a `dgram` socket that is already connected before the guard installs. It stops accidents and drift, not a hostile dependency; Docker publishing on `127.0.0.1` only is the second layer.
- **Real is owner-run and read-only.** The one outbound origin is `SF_LOGIN_URL` from this lab's own `.env`; netguard allows that one host and nothing else. https only (plain http for a loopback stub); no credentials, path or query in the origin; no IP literal, trailing-dot or local name, no port 0; a DNS answer that is private, loopback, link-local, carrier-grade, documentation, NAT64, 6to4, site-local, discard or an IPv4-mapped form of those is refused; no redirect is ever followed (so none cross-origin); an instance URL other than the configured origin is refused; the answer is capped at 1 MiB and 10 seconds; the SOQL is two fixed `SELECT` statements. A Salesforce answer is never echoed raw: every value shown from it goes through a credential check, so a JWT or anything the shared masker would change is replaced by a fixed note. A confirm gate (you type the org host) stands in front of the call, switching to Real contacts nothing, and Docker never opens in Real.
- **The private key is write-only.** It is read from the file named by `SF_PRIVATE_KEY_PATH` when a read runs, used to sign an RS256 JWT with `node:crypto`, and dropped. It is never returned, logged, cached, put in an error message or a hop. The lab never generates a key pair (the mock's keys and certificates are fingerprints of fixed strings). The Salesforce access token is used for two GETs and dropped; the only tokens ever shown are the mock's own, labelled MOCK. The consumer key a visitor types is compared and never echoed.
- **User text is inert and bounded.** Typed text has control and bidi characters stripped, is length-capped, and is refused whole (never echoed) if the shared masker would change it, i.e. if it looks like a credential. Values used as object keys are checked with `Object.hasOwn` or a fixed id shape; every walker is iterative; no `eval`, `Function` or `vm`; no regular expression is built from input. Bodies are 32 KB, any text in a body 400 characters, a key 80, a list 20, an object 40 keys, nesting 6 (over: 413, nothing runs).
- **Downstream failures are named.** An unreachable, slow, redirecting, oversized or rejecting upstream answers `{error, message}` JSON with a 502 or 504; a mock sign-in failure inside Privilege's own calls is a 502 `salesforce_sign_in_failed` with the cause and fix. A missing static file is a JSON 404, a wrong method a 405 with `Allow`, a charset other than utf-8 a 415.
- **Workspaces.** The `X-Workspace` id (default `default`) keeps one visitor's state apart; an id that looks like a credential is a 400 before a slot exists. At most 500 workspaces for 1 hour each.
- **No real identifiers.** People are fictional with emails on the org's own `.example` host (never `example.com`); the org lives on a `.example` host; the mock consumer key is `3MVG9-MOCK-...`. A doctor check scans the filled story in every vertical.
- **Every product claim is labelled** "observed on one org and one Privilege build, UNVERIFIED as a product claim" in the data and in the banner; wording that was not captured is null, not invented.
- The server writes no file (a test greps for write calls). It reads only its own `.env`, with `util.parseEnv`, taking the six listed keys.
