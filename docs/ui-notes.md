# Web UI notes

Pages (hash routes, one shell, banner first on every page and in presenter mode): Support P1, Scenarios, Connect, Link, Grant and revoke, Diagram, Real. The header carries the Mock / Real toggle (two buttons, the current mode pressed) on every page; a press is `POST /api/mode` with exactly `{source}`, then info, story and state are loaded again. The Mock banner is the only honesty text: "Simulated: every behaviour shown was recorded in one real Privilege and Salesforce run."

- **Support P1** is the first page. Three panels together: (a) the engineer's Salesforce view, (b) Privilege (latest request with its note, the policy, the receipts with their history, the reconciliation line, the refusal when there is one) and (c) "The old way", a static narrative marked "Narrative: not a Privilege claim". The controls are Request access (note up to 200 characters, an end time chosen from lab-clock times) and End access. Cases visibility is never a page flag: the server's `state.support.canSeeCases` is derived from the engineer's `Case Read Access` assignment, and `cases` is `null` while denied (no title, no count). The three beats (no access, access for the job, no access again and a receipt) come from `web/src/support.js` and drive the beat strip and presenter mode.
- On the first visit in a fresh world the page starts from the story's own starting point with `POST /api/scenarios/support-p1/run` and `upTo: 0` (an org connected to Privilege, the engineer linked). If the world was changed on another page it offers "Set the scene" instead of replacing it silently.
- End access is `policy.delete`. The page shows "Revoke pending, access still live" and then asks for a refresh once (`app.reconcile`) after 2.5 seconds; "Refresh receipts" does the same by hand. A refused refresh (for example Privilege cannot sign in) is shown and not repeated.
- All writes go through `POST /api/actions` (`refusalsAs200: true`, so a refusal the visitor asked for is data, not a console error). Scenarios use `POST /api/scenarios/:id/run` with `upTo` (Run shows step 1, Next step adds one).
- Every JSON pane is the shared `JsonPane` (opens on JSON in this lab). Nothing is decoded or parsed by hand. Every dialog is the shared `FloatingDialog`; the talk track is the shared `TalkTrackDialog`.
- The diagram is `GET /api/diagram?name=<name>&vertical=<v>` (diagram-studio data shaped as `{title, intro, nodes[{id,label,kind,x,y}], steps[{from,to,label,title,say}]}`); names used: `connect-and-link`, `grant-and-revoke`. The page draws nothing the data does not list.
- User text is rendered as text (`visible()`); the note box is capped at 200 characters and the server refuses more.
- Tests run the repo's own Express app in process (`web/src/test/harness.js`), so a click meets the real engine. Real is an in-process fake; nothing leaves the machine.
- One port (7835): `npm run dev -w web` rebuilds `web/dist` on change and the running API serves it.
