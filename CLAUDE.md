# salesforce-privilege-LAB

Demo-tier standalone app (port **7835**, one port, 127.0.0.1 only; catalog id placeholder `D000`, the owner assigns it). The **Support P1** story: a support engineer with the Minimum Access profile has no access to Salesforce Cases, asks Privilege for `Case Read Access` with a note and an end time, works the P1, ends the access (deletes the policy) and is left with a receipt; plus the connecting, linking and grant/revoke pages behind it, against a MOCK org. Fork of curtismu7/saas-access-LAB (scaffold and vendored shared components). **Only what the one real run showed (`docs/setup-guide.md`) is modelled.** Spec and evidence: `docs/specs/2026-11-22-support-p1-story*.md`. The one honesty text is the Mock line of the Real-or-mock modal (shared `mode-modal`, the page opens on it once per mode per browser session; there is no persistent banner); there are no label chips and no label fields in the API. Never present anything here as a Ping statement.

- Default story: **AirGuard Airlines** (airlines vertical, host `airguard`, emails `@airguard.example`; owner 2026-11-28). Four vertical packs in `server/src/cast.js` (airlines, finance, health, retail); `DEFAULT_VERTICAL` and the web default (`useLab.js`) are `airlines`; an unknown id falls back to it. Retired names (earlier packs' brands and the earlier airline brands) are swept in `server/test/airlines.test.js`. `docs/talk-track.md` and `content-pack.json` are generated (`npm run talk-track`, `npm run content-pack`).
- Run: `./scripts/run.sh` (http://localhost:7835; it builds the UI if `web/dist` is missing). Test: `npm test` (server `node --test test/*.test.js`, a glob; web vitest against the real Express app in process; scripts). Build: `npm run build`. UI standard: `bash scripts/check-ui-standard.sh`. Preflight `npm run doctor`. Reset `npm run reset`. Docker: `docker compose up --build -d`. Node 26 only. Heavy work on the Air: `air-test . -- npm test` (git add new files first).
- **Built**: engine, API, UI (seven pages: Support P1, Scenarios, Connect, Link, Grant and revoke, Diagram, Real; header Mock/Real toggle, Presenter, talk track), Docker wiring (Mock by default, Real owner-run from the lab's own `.env` + `secrets/`, made by `scripts/setup-real.sh`, `docs/real-mode.md`), shelf entry and ship text (`docs/shelf-entry.json`, `docs/ship-notes.md`, not applied). **Not done**: the public repo (needs owner approval; the header Help link points at it and works only once it exists), the real catalog id (`D000` is a placeholder), the registrations. Diagrams are `server/diagrams/*.json` (diagram-studio/1, loaded by name through `GET /api/diagram`): `connect-and-link` and `grant-and-revoke`; UI notes in `docs/ui-notes.md`.
- Core: `engine.js` (the mock Salesforce org + mock Privilege app + lab clock, deterministic, no I/O; ids are fixed: sfu-1 admin, sfu-2 the support engineer, sfu-3 shared-email user, ps-1 `Case Read Access`, ps-2..3 seeded sets, ps-4 the first one a scenario creates; Cases visibility is DERIVED in `_support()` from the engineer's assignment, never stored), `actions.js` (the one dispatch: API, scenarios and tests; `support.requestAccess` is the story's op), `data.js` (banner, `CASES`, OUTCOMES with cause and exact fix, troubleshooting table, talk track), `scenarios.js` (12 scenarios as data, `support-p1` first, presets, `runScenario`), `cast.js` (three vertical packs, `{{tokens}}`, the case titles), `real.js` (Real read: RS256 JWT bearer over node:http(s), SSRF guard, caps), `netguard.js`, `app.js` (one `ROUTES` table), `story.js`, `doctor.js`, `health.js`, `workspaces.js`, `settings.js` (this lab's own `.env`), `config.js` (`defaultSource`).
- Rules that bite: Mock is the default and makes zero outbound calls (netguard + tests). Real is owner-run and read-only: NEVER run it, never use a live credential; tests use the in-process stub (`server/test/stub.js`). The private key is write-only (never returned, logged or cached); no EC key generation anywhere. `POST /api/mode` takes exactly `{source}`; Real not configured is 409; default Real if configured else Mock; Docker forces Mock (`SFPRIV_DEFAULT_SOURCE`). `/api/real/read` needs `{confirm: <host>}`. Downstream failures are `{error, message}` JSON with 502/504. The shared masker (`server/src/shared/`, copied unchanged from shared-masker 1.4.0) refuses credential-shaped typed text and is never edited here. Vendored files under `web/src` (top-menu, JsonPane, VerifyMark, floating-dialog, diagram-kit, standalone-ui.css) are byte-identical with their pins: re-vendor, never edit. People are fictional with emails on the org's own `.example` host (never `example.com`), the org is on a `.example` host.
- Run observability (rule 27): `web/src/run-observability/` and `server/src/runObservability.js` are vendored byte-for-byte from `AI-DEMO-Standalone/shared/run-observability/` and pinned (`scripts/run-observability.pin.test.mjs`; `node scripts/run-observability-checkPin.mjs .`). This lab reads no logs (Real runs nothing), so it vendors the core only: no readers file, no reader setting anywhere, and the `runObservability.js` entry-test exemption is by exact name in `server/test/entry.test.js`. Rows come from `server/src/runObs.js` (one action = one run on `POST /api/actions`; only grants and revokes are policy decisions; the GET record route is `/api/actions/run`). One stdout line per policy-point decision.
- Removed on purpose (do not bring back without a new real run): the reaper and expiry, drift (discovered/orphaned), the sign-in outcomes the guide does not record (wrong username, inactive or unlicensed user, expired certificate, missing `api` scope, JWT not enabled), the exact 10-minute boundary (the mock is active after 2 minutes, inside the guide's 2 to 10), the sign-in check order, the durations list, "the next reconcile clears pending". A setup the guide records no failure for is the lab's own `not_modelled` refusal. Wording the guide did not capture (the exact Salesforce error for a missing refresh_token scope, a certificate problem) is `null` in `OUTCOMES`, on purpose.
- Receipts read only what the guide records: Granted, then "Expired / Revoked". "Revoke pending, access still live" is on the POLICY only, and only the visible Refresh receipts button (`app.reconcile`) completes the removal (no auto-refresh; Sync does not). The reconciliation shows only `confirmed`.
- The note on a request is the lab's own step; never claim Privilege stores it. The end time is only the "until" date on the receipt; never claim it ends access.
- `scripts/setup-real.sh` is owner-run: never run it with real values, never read or write a real `.env` or key. `scripts/setup-real.test.mjs` runs it with made-up values in a temporary directory against the loopback stub.
- Run conformance by hand: `node ~/Development/demo-kit-base/scripts/conformance.mjs . --new --tier=Demo`.
