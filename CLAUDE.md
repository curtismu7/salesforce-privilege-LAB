# salesforce-privilege-LAB

Demo-tier standalone app (port **7835**, one port, 127.0.0.1 only; catalog id placeholder `D000`, the owner assigns it). A rehearsal of connecting a Salesforce Developer org to PingOne Privilege and granting then revoking a permission set for a time window, against a MOCK org. Fork of curtismu7/saas-access-LAB (scaffold and vendored shared components); one platform, new engine. **Every behaviour is "observed on one org and one Privilege build, UNVERIFIED as a product claim"** (source: `docs/setup-guide.md`, `skills/privilege-salesforce-setup/`). Never present it as a Ping statement.

- Run: `./scripts/run.sh` (http://localhost:7835; it builds the UI if `web/dist` is missing). Test: `npm test` (server `node --test test/*.test.js`, a glob; web vitest against the real Express app in process; scripts). Build: `npm run build`. UI standard: `bash scripts/check-ui-standard.sh`. Preflight `npm run doctor`. Reset `npm run reset`. Docker: `docker compose up --build -d`. Node 26 only. Heavy work on the Air: `air-test . -- npm test` (git add new files first).
- **Built**: engine, API, UI (six pages: Story, Connect, Link, Grant and revoke, Diagram, Real; header Mock/Real toggle, Presenter, talk track), Docker wiring (Mock by default, Real owner-run from the lab's own `.env` + `secrets/`, `docs/real-mode.md`), shelf entry and ship text (`docs/shelf-entry.json`, `docs/ship-notes.md`, not applied). **Not done**: the public repo (needs owner approval; the header Help link points at it and works only once it exists), the real catalog id (`D000` is a placeholder), the registrations. Diagrams are `server/diagrams/*.json` (diagram-studio/1, loaded by name through `GET /api/diagram`, every step with a `basis`); UI notes in `docs/ui-notes.md`. Scenarios and talk-track items carry `basis` + `label` too.
- Core: `engine.js` (the mock Salesforce org + mock Privilege app + lab clock, deterministic, no I/O; ids are fixed: sfu-1 admin, sfu-2 demo user, sfu-3 shared-email user, ps-1..3 seeded sets, ps-4 the first one a scenario creates), `actions.js` (the one dispatch: API, scenarios and tests), `data.js` (claims, OUTCOMES with cause and exact fix, troubleshooting table, talk track), `scenarios.js` (17 scenarios as data, presets, `runScenario`), `cast.js` (three vertical packs, `{{tokens}}`), `real.js` (Real read: RS256 JWT bearer over node:http(s), SSRF guard, caps), `netguard.js`, `app.js` (one `ROUTES` table), `story.js`, `doctor.js`, `health.js`, `workspaces.js`, `settings.js` (this lab's own `.env`), `config.js` (`defaultSource`).
- Rules that bite: Mock is the default and makes zero outbound calls (netguard + tests). Real is owner-run and read-only: NEVER run it, never use a live credential; tests use the in-process stub (`server/test/stub.js`). The private key is write-only (never returned, logged or cached); no EC key generation anywhere. `POST /api/mode` takes exactly `{source}`; Real not configured is 409; default Real if configured else Mock; Docker forces Mock (`SFPRIV_DEFAULT_SOURCE`). `/api/real/read` needs `{confirm: <host>}`. Downstream failures are `{error, message}` JSON with 502/504. The shared masker (`server/src/shared/`, copied unchanged from shared-masker 1.4.0) refuses credential-shaped typed text and is never edited here. Vendored files under `web/src` (top-menu, JsonPane, VerifyMark, floating-dialog, diagram-kit, standalone-ui.css) are byte-identical with their pins: re-vendor, never edit. People are fictional with emails on the org's own `.example` host (never `example.com`), the org is on a `.example` host.
- Label states (additive API fields `basis` + `label`): `observed` (the guide records it), `lab-inferred` (wrong username, inactive/unlicensed user, expired certificate, api scope, JWT not enabled, the 10-minute boundary), `lab-invented` (reaper expiry, reconcile clearing pending, case-sensitive matching, discovered/orphaned, durations, authorized-user rights not checked; listed in `GET /api/story` `labInvented`). The sign-in check ORDER is lab-chosen (`signInOrder`).
- Wording that the guide did not capture (the exact Salesforce error for a missing refresh_token scope, a certificate problem, a wrong username) is `null` in `OUTCOMES`, on purpose. Do not invent it.
- Run conformance by hand: `node ~/Development/demo-kit-base/scripts/conformance.mjs . --new --tier=Demo`.
